# sing-box 网络安全审计修复实施 Prompt（2026-11-19）

请在 `Linmiao010/sing-box` 仓库中，依据[网络安全审计报告](../docs/network-security-audit.md)实施修复。报告基于提交 `b0a8951`。先核对当前提交和工作树，再从实际安装、菜单、更新和订阅生成入口追踪下列问题。对仍存在的问题修改代码并验证。已修复的条目给出当前实现及回归证据。涉及旧部署行为变化的步骤，更新[安全迁移与验收](../docs/security-migration.md)。

沿用报告编号。优先处理高危项 1、2、3、4、8，其中第 8 项限多用户 VPS。中高危项为 5、9、10。同一处服务端配置会被多个入口写入，在合并路由和凭据变更时一并考虑第 10 项的锁边界。保留已建立的发布物摘要校验、SSH 主机密钥校验、订阅读写权限隔离和客户端证书验证。

## 修复任务与验收条件

### 1. 限制服务端代理的出站目标

在 `sb.sh` 的 `inssbjsonser()` 与 `serv00_runtime.py` 的 `server_config()` 中修改服务端路由。在任何可提前选定直连、SOCKS 或 WARP 的规则之前，拒绝回环、私网、链路本地、`100.64.0.0/10` 以及部署明确使用的其他元数据地址。域名须先取得并检查解析结果，实际拨号只使用已检查且允许的地址。保留现有 IPv4/IPv6 优先策略，同步修正 `ip_priority_get()`、`ip_priority_patch()` 对固定规则位置的依赖。

按实际服务端内核生成规则。1.10.7 使用旧式 `block` 出站，1.14.3 使用 `reject` 动作。`SERV00_CLIENT_SERIES` 只控制客户端格式。用本地可控 DNS 和地址样例验证 IP 字面量、解析到受限地址的域名及允许的双栈目标，覆盖原有分流和切换地址族后的行为。分别记录两个版本的配置检查与路由行为结果。

### 2. 保护 Serv00 的 Argo 回环源站

检查 `acquire_state()`、源站监听和 cloudflared 的启动生命周期。优先选择宿主分配给本账户的端口。复用 `vmess_port` 的前提是宿主对回环绑定实施 UID 保护，且公网单播地址和回环地址能够分别绑定。将这两个前提列入目标宿主验收。

临时隧道在启动参数配置 HTTPS 回源、证书名称和信任根。固定隧道由 Cloudflare 控制台下发回源配置，写清控制台修改、连接器读取信任根和切换顺序。同步更新脚本提示及迁移手册。分别验收两种模式的可信证书成功、错误证书被拒，以及重启、更新、改端口和轮换期间的源站切换行为。

### 3. 修正 WARP 状态探测与 DNS 修改

让 `warpcheck()` 对指定地址族直接发起有超时的 HTTPS 请求，忽略 curl 用户配置和代理，校验证书，只接受有效的 `warp=` 状态。探测失败保留为未知。操作前记录 `wg-quick@wgcf` 和 `warp-go` 的活动状态，结束时只恢复原本活动的服务，保留原有自启策略。

在真正写 DNS 的 `v4orv6()` 中，以本机无全局 IPv4 地址和管理员显式确认作为更换 DNS64 的前提。先备份原内容及符号链接关系，再安全替换并提供恢复步骤。用服务命令替身和临时文件验证探测超时、管理员拒绝、原服务停用及符号链接四种情况，确认失败探测也不会覆盖已知的服务器地址。

### 4. 保护 Telegram、二维码和订阅验收使用的凭据

在 `tgsbshow()` 校验 Bot Token 和 chat ID，按报告的格式规则兼容数字 ID、负数群组 ID 和合法的 `@用户名`。凭据单独以 `0600` 保存，`sbtg.sh` 使用 `0700` 静态脚本。Telegram 的 HTTPS URL 与消息正文经受限文件或文件描述符传递，移除未使用的 HTML 解析模式。节点及订阅二维码通过标准输入交给 `qrencode`，HTTPS 订阅验收也从受保护输入读取带令牌的 URL。

用虚构凭据验证非法输入被拒、普通文本中的尖括号可发送，并检查外部进程参数及日志。分别执行开启推送和关闭推送后的常规订阅刷新，确认 Bot Token、聊天标识、节点链接、订阅路径令牌及可选的客户端 WARP 私钥不会出现在命令行中。

### 5. 收紧菜单 14 的启动、探测和进程停止逻辑

在 `inssbwpph()` 校验端口和两位大写国家代码，用权限为 `0700` 的固定启动脚本及独立参数替换从日志拼装的命令。出口探测使用校验证书的 HTTPS，核实 HTTP 状态并用 `ip_literal_valid` 验证返回值。检查安装、重置、卸载和 `cfargo()`，仅停止归属于本项目的进程。按端口定位时先校验端口，再匹配完整的二进制路径和端口参数。

验证 cron 与 Alpine 启动路径均能正确传参，错误页判为探测失败。配置缺失、端口为空或与另一端口前缀相同时，无关进程应继续运行。

### 6. 校验订阅输入并统一临时 Argo 域名解析

检查 `changeym()`、`cfargoym()`、`vmesscfadd()` 和 `sb_client()`。Reality 域名、固定隧道域名及 `ca.log` 的值使用域名校验，优选地址只接受合法域名或 IP。覆盖菜单输入和已落盘的旧值。`cfymjx.txt` 若用于指定 Host/SNI，要让其进入实际生成路径，否则清理无效设置并同步提示。

从当前隧道日志中提取最近一条完整、合法的 `*.trycloudflare.com` 主机名。VPS 临时隧道回源与监听地址统一为 IPv4 回环 `127.0.0.1`，外部探测及重定向仅用 HTTPS，客户端 `urltest` 也使用 HTTPS。解析生成的 YAML、JSON 和分享 URI，核对合法值的实际用途、非法值被拒、日志行数变化及相似后缀域名的处理。

### 7. 清理临时凭据并保护探测进程参数

在 `kp.sh` 本机与远端部署片段、`gitlabsub()` 和 `changewg()` 中，让 HUP、INT、TERM 进入已有的退出清理路径。在 `tools/network_probe.py` 提供从标准输入或受限文件读取敏感 URL 和代理认证的入口，下传 curl 时继续使用受保护输入。HTTPS 起始请求只允许 HTTPS 重定向。

用虚构凭据验证正常退出和上述信号下的清理结果。分别检查 Python 父进程与 curl 子进程的参数，在本地重定向样例中确认 HTTPS 降级会被拒绝。

### 8. 让 Caddy 只读提供三个白名单订阅文件

优先让 Caddy 直接读取当前发布快照，保留三个精确的令牌路径和其他路径返回 404 的行为。若确需独立后端，用受保护目录内的 Unix socket 验证访问边界。覆盖项目管理的 Caddy 和系统共享 Caddy，保留新快照切换及发布失败后的恢复行为。

验证三份文件与当前快照内容一致，轮换后旧令牌失效，额外路径返回 404。快照或后端不可用时，客户端应收到错误；用隔离环境确认请求不会转发到普通用户可绑定的 TCP 端口。

### 9. 保留防火墙原有限制的执行顺序

检查 `tools/firewall.py` 的 iptables、UFW 和原生 nftables 实现。项目放行位置由管理员确定，使已有的来源封禁、接口限制及限速先执行。顺序无法可靠确定时，保留原策略并提示手动放行。用同一个节点端口分别验证受限来源仍受限、允许来源仍可访问，记录实际验证的后端及地址族。

### 10. 防止并发回滚恢复旧 UUID

梳理 `config_apply()` 及所有写入同一组服务端配置的入口。共用一把写锁，从读取当前状态开始覆盖候选生成、提交、服务重启、防火墙同步和失败回滚。现有 `subscription.lock` 保护订阅发布，检查两者同时使用时的加锁顺序。

用两个重叠的管理会话模拟 UUID 轮换与端口或证书变更，控制其中一次提交失败。轮换已成功时，运行配置、`sb10.json`、`sb11.json` 均须保留新 UUID，正在运行的服务使用该有效配置。

### 11. 让管理员的停服决定在调度和重启后生效

每日维护只重启正在运行的实例。菜单 6 的停服操作同时清理项目的定时重启及对应自启项，并核实服务已停止。覆盖 systemd 与 Alpine/OpenRC 的旧安装，检查下一次调度及开机后节点仍然关闭，显式重新启用时能恢复服务。

### 12. 默认关闭客户端 Clash API

检查 VPS 与 Serv00 生成的完整 sing-box **客户端**订阅。默认关闭 Clash API。需要面板的用户在设备本地启用回环监听并生成该设备独立的随机密钥。验证两种来源的默认订阅均未启用接口，并验证显式启用后未认证请求被拒、设备自己的密钥可用。

### 13. 防止 UDP 跳跃端口覆盖已有服务

在 `tools/firewall.py` 写入状态或应用规则前，按地址族、目标地址及 UDP 端口区间检查 Hysteria2、TUIC、宿主监听和已有转发的冲突。覆盖部分重叠、端点重合、通配监听以及可共存的不相交区间。冲突时显示实际冲突区间，核对磁盘状态和系统规则均保持原值。

### 14. 核对旧 Serv00 目录导入的 WARP 策略

历史目录曾允许其他账户写入，收紧为 `0700` 后仍需确认旧内容来源。迁移时从可信备份恢复，或显示拟继承的匹配条件、远程规则集 URL 及出站供管理员确认。来源无法确认时暂停导入该策略，并说明哪些流量会受影响。分别验证可信备份、人工确认和来源不明的迁移路径，确保节点 UUID 的轮换不会隐式批准旧策略。

## 客户端分流规则的供应链风险

检查 VPS 与 Serv00 完整客户端配置中的地域规则及关联 DNS 路由。对于要求直连范围可审计的部署，使用受审查的完整提交固定规则来源，随发行显式升级，或分发已校验的本地规则。若保留跟随上游可变分支的模式，在订阅说明中写明哪个上游可改变直连和 DNS 范围，以及更新何时生效。检查两端生成的配置是否体现所选策略。报告记录的是运行期信任关系，没有证据表明上游已被篡改。
