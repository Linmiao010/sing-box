# sing-box 网络安全修复实施提示词

请在 `Linmiao010/sing-box` 仓库中实施以下修复，交付代码、针对已知问题的回归验证，以及现有部署的迁移步骤。审查基线为 `4a8e812`。开始时核对当前提交、工作树和实际调用路径。若某项已经修复，用现有代码和验证结果关闭该项。文中的文件、函数和配置字段是定位线索。

实施范围包括 VPS 主脚本、Serv00 安装和保活脚本、管理页面、订阅生成器及配套自动化。沿用现有配置读取、候选配置检查、原子替换和失败回滚逻辑。把操作手册中受影响的命令与默认行为一并更新。线上令牌撤销、证书签发、防火墙恢复和服务器部署由部署者按迁移步骤执行。

## 第一批修复

### 1. 保留主机防火墙和 SSH 管理通道

`sb.sh` 的安装路径在端口确定前调用 `openyn()`，直接回车会进入 `close()`，停用防火墙、清空规则并尝试关闭 SELinux 强制模式。主程序卸载还会清空整条 NAT `PREROUTING` 链。

- 默认沿用主机策略。管理员显式选择自动放行时，等实际端口确定后，使用当前防火墙后端，按启用协议、传输层和地址族添加规则。系统服务、SELinux、已有 SSH 放行规则和其他应用的转发规则均由原管理方维护。
- 为项目规则添加可识别的标记或专用链。安装重试、改端口、UDP 端口跳跃和卸载只处理本项目拥有的条目。旧版缺少归属标记的 DNAT 规则列给管理员核对。对于旧版已经清空的策略，迁移说明应指导管理员通过可用的 SSH 会话或云控制台，依据备份和实际端口恢复。
- **验收**　在隔离环境预置 SSH 放行规则和一条其他应用的 NAT 规则，比较安装、重复安装、改端口、卸载前后两条规则及默认策略。检查 IPv4、IPv6 的结果，并注明所测防火墙后端。

### 2. 将 WebSocket 路径与节点密码分开

`sb.sh` 用同一个 UUID 为多个协议认证，又将它写入 VMess WS 路径。默认自签分支令 VMess 的 `tlsyn=false`。Serv00 的直连和 Argo 模板也将 UUID 写入路径。明文握手和代理访问日志都可能暴露这个值。

- 新装独立生成并持久保存随机 WS 路径。配置刷新沿用已保存的路径。检查服务端模板、`config_patch_identity()`、`sb_client()`、单节点分享链接、Serv00 和 Argo 生成逻辑，确保各端使用同一个路径。明确区分公网 WSS 直连与隧道回环后端，按实际拓扑选监听地址和端口。
- 旧配置按入站 tag 读取实际路径，识别有无前导斜杠的旧默认值，并区分服务端路径与客户端附加的 early-data 查询参数。迁移旧默认路径时轮换可能已暴露的共享 UUID，更新所有引用该凭据的协议、链接和订阅。保留用户自定义且未包含凭据的路径。把会导致客户端掉线的轮换做成显式迁移动作，成功后提示刷新订阅或重新导入静态链接。
- **验收**　用虚构 UUID 分别生成新装、旧默认路径、自定义路径三组配置。解析服务端和客户端产物，确认路径一致且不含认证值，重复生成保持稳定；验证轮换后新客户端可用、旧凭据失效，候选配置失败时仍保留原有可用配置。

### 3. 将 GitLab 发布权限与订阅读取权限分开

`gitlabsub()` 用同一令牌推送仓库，并把它放进三个订阅 URL 的 `private_token` 参数。该令牌还会落入 Git remote 地址和生成的 Expect 脚本。

- 写凭据仅供服务端发布，使用受限的凭据文件或合适的 Git 凭据机制。公开给客户端的入口优先复用现有 Caddy HTTPS 分发；保留私有 GitLab 直读功能时，使用项目范围、只读且受目标下载接口支持的独立凭据。
- 覆盖首次设置、后续推送、快捷显示、二维码和 Telegram 通知。迁移时清理本机保存的旧 remote、脚本与分享链接，列出 GitLab 端撤销旧令牌的步骤。若多台 VPS 共用令牌，先替换所有发布端的凭据。
- **验收**　给发布和读取各设一个不同的测试值。发布流程可更新三个文件；客户端文件、分享链接、二维码原文、通知和日志中均找不到发布凭据。用本地替身验证只读身份不能推送，单列仍需 GitLab 实际账号确认的权限。

### 4. 收紧 Serv00 网页面板，并修复实际部署入口

`app.js` 的公开 GET 路由可执行保活、重启和重置端口，进程页返回原始 `ps aux`。固定 Argo 隧道的参数可能带 token。安装器和保活器还从另一仓库的可变分支下载面板，再按固定行号替换内容。

- 默认仅暴露返回最少信息的只读健康检查。将定时保活交给现有调度机制，将重启、改端口交给 SSH。若保留远程管理功能，使用经验证的 HTTPS、独立管理凭据和经鉴权的 POST，对重复操作限制并发。订阅读取凭据与管理凭据分别生成。移除原始进程输出，响应和日志使用脱敏状态。
- 检查 `serv00.sh`、`serv00keep.sh`、`kp.sh`、`app.js`、`workers_keep.js` 和 `.github/workflows/main.yml`。让安装、更新和保活使用同一受审版本，替换按行号编辑 JS 的做法。同步修改旧 URL 调用方。若保留重置路由，修正异步回调中未传入的 `res` 和提前报告成功的问题。
- **验收**　在本机用模拟操作函数记录调用数。访问健康页、访问旧 GET 地址、提交未授权请求时，重启和端口变更调用数均为零。响应和日志不包含进程参数、订阅内容或测试令牌；按实际安装流程生成的面板也满足这些条件。

## 其余修复与验收

| 项目 | 实施要求 | 验收条件 |
|---|---|---|
| 自签证书与客户端 TLS | 核对 Hysteria2、TUIC、AnyTLS、Trojan 在 sing-box JSON、Mihomo YAML、分享 URI 及 Serv00 中的生成分支。保留可信域名证书方式。自签模式按各客户端及版本支持的方式分发受信证书或固定指纹，并核对证书名称。Hysteria2 单节点 URI 已有指纹；生成其他格式时核对字段要求的是整张证书还是公钥摘要。 | 在回环环境分别使用受信证书和另一张同名证书。正确证书能连接，错误证书握手失败。区分完整订阅与单节点链接，覆盖项目兼容的 1.10 和新版分支，并列明已实际测试的客户端版本。 |
| 公网 HTTP 订阅 | `sub_httpd_write()` 在 IP 模式仅传端口，BusyBox 会对外提供明文配置。公网分发优先使用已有 Caddy HTTPS；需要本地 HTTP 后端时显式绑定回环。迁移先验证 HTTPS 端能读取最新三份文件，再关闭旧 HTTP 入口。已通过不可信网络发出的订阅同时轮换路径令牌和节点凭据。 | 从隔离网络核对监听地址、HTTPS 证书和三个文件的内容。已有 HTTP 部署能够迁移；迁移成功后旧端口不能再从非回环接口提供配置，旧令牌失效。 |
| Mihomo 默认局域网共享 | VPS 和 Serv00 生成的完整客户端配置默认关闭 `allow-lan`。主线启用的 DNS 绑定回环地址。需要共享时由用户显式启用，限制允许的网段，并为代理配置认证。 | 默认启动后，代理和 DNS 的监听符合单机使用预期。检查 Serv00 自身的 DNS 启用状态；共享模式下只允许管理员指定的来源。 |
| 安装和更新的供应链 | 检查 README 首装、`lnsb()`、内核安装及切换、Caddy 两条下载路径、附带二进制、ACME/WARP/BBR 和 Serv00 下载点。脚本锁定受审版本；下载内容在解包、执行或调用 `version` 前，用受信发布签名或随受审版本维护的摘要清单验证。保留现有候选文件与原子替换机制。 | 用本地发布物模拟成功下载、内容不符和校验信息缺失。后两种情况终止更新，候选程序执行次数为零，原程序仍可用。记录清单的信任来源和版本更新方式。 |
| SSH 主机身份与自动化日志 | `kp.sh`、`SSH.yml`、`serv00.yml` 的所有 SSH 调用使用预先核实的 `known_hosts` 并严格验证；口令或密钥由运行环境安全注入。清除完整远程命令、节点清单及带凭据 URL 的日志输出。Worker 和工作流使用 HTTPS 并验证证书。根目录两个 YAML 是用户可选用的模板。 | 在隔离环境用两把不同的测试主机公钥验证匹配时继续、未知或变更时拒绝。自动化的成功和失败日志均只含脱敏标识与状态。 |
| 本地权限与 WARP 私钥 | Serv00 的私有工作目录改为账户专用的 `0700` 目录。主线和 Serv00 的凭据、配置、备份及临时文件按实际读取身份设置 `0600` 或最小必要组权限。发布服务只读取三份订阅产物。清除 Serv00 写入的固定 WARP 私钥和主线 `warpwg()` 的固定回退密钥，为每个实例注册或导入独立密钥。 | 用两个本地测试账号核对普通账号无法读取凭据或替换启动文件，发布进程仍能读取订阅。模拟 WARP 注册失败，保留已有有效配置或明确停用该出站，并保留依赖 WARP 的分流意图，避免静默改为直连。 |

## 验证与交付

优先复用当前检出已有的配置生成、订阅发布、内核更新和 Serv00 回归测试。基线的 `.gitignore` 忽略了 `tests/*`，请确认准备交付的关键回归用例在干净检出中也能取得和执行。Shell 与 JS 语法检查用于发现解析错误；权限、监听地址、证书和操作鉴权分别做行为验证。测试使用虚构凭据、临时目录、回环服务或隔离网络，保持开发机本身的防火墙和 SSH 配置完整。

请按以下三项交付结果。

1. **修复结果。** 逐项列出改动文件、默认行为、已执行的验证及结果，标明未覆盖的平台或客户端。
2. **旧部署迁移顺序。** 分别说明单机 VPS、GitLab 订阅、Serv00 的操作步骤，标出会中断现有连接的步骤。给出分发新配置、停用旧入口、撤销旧凭据的时机。回滚可恢复服务程序与配置，已经泄露或撤销的凭据须使用新值。
3. **线上待核验项。** 单列云安全组与双栈可达性、真实证书签发、GitLab 令牌撤销、Serv00 宿主权限与实际部署版本。每项提供预期结果，并区分本地验证与需要部署者执行的检查。
